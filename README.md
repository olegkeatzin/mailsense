# MailSense — почтовый помощник с ИИ-аналитикой и документооборотом

Система для аппарата организации: забирает входящую корреспонденцию из служебных ящиков,
распознаёт и анализирует письма **локальными** ИИ-моделями (без внешних сервисов), ведёт журнал
входящих документов, резолюции и контроль исполнения поручений.

Состоит из двух частей: **сервер документооборота** (Docker, PostgreSQL, служебные ящики) и
**клиент на рабочем месте** (Electron, личные черновики и подпись остаются у работника).
Версия: **0.1.4**.

## Что умеет

- **Почта**: IMAP и собственный клиент POP3 (none/ssl/starttls), несколько ящиков, вложения,
  треды по `Message-ID`. POP3 обязателен в проде — IMAP есть не везде; письма с сервера не удаляются.
- **ИИ локально**: двухступенчатый конвейер — OCR-модель читает сканы и PDF, модель выжимки даёт
  краткое содержание и реквизиты (номер, дата, корреспондент). Адрес и модель у OCR **свои**,
  отдельно от выжимки. Облачные провайдеры не используются.
- **Документооборот**: журнал входящих (как бумажная книга), автоматическая нумерация `вх{N}`
  со сбросом каждый год, резолюции с утверждением подписантом, поручения исполнителям, сроки,
  отчёты и закрытие только подтверждением аппарата.
- **Права и аудит**: роли администратора, аппарата (секретариата), руководителя, подписанта,
  исполнителя; почту видят только аппарат и администратор; каждое изменение пишется в аудит
  в той же транзакции.
- **Почта для СЭД (решение Р24)**: работник сам выбирает, с какого ящика уходят письма по
  документообороту; администратор выдаёт, из чего выбирать. «Первый подходящий» ящик не
  подставляется — официальное письмо не уходит с чужого адреса.
- **Внешние ящики** (например, Яндекс по IMAP) подключать можно, но в документооборот их письма
  не попадают: очереди СЭД видят только служебные ящики и личную почту смотрящего.

## Топология

```
  рабочие места (Electron)                     сервер (Docker)
  ┌───────────────────────────┐   REST/HTTPS  ┌────────────────────────────────┐
  │ черновики, шаблоны,       │ ◄───────────► │ журнал, резолюции, поручения,  │
  │ подпись — ЛОКАЛЬНО        │               │ служебные ящики, аудит         │
  │ почта, задачи, СЭД        │               │ PostgreSQL · локальные ИИ      │
  └───────────────────────────┘               └────────────────────────────────┘
```

Сервер держит служебные ящики аппарата и является единственным владельцем документооборота.
Клиент может быть и просто браузером — SPA отдаёт тот же сервер на порту 8123.

## Быстрый старт: сервер с нуля

Нужен Docker (Linux или Docker Desktop) и доступ к серверу по сети. Данные складываются в обычные
папки на хосте, поэтому бэкап — это копирование каталогов.

```bash
git clone https://github.com/olegkeatzin/mailsense.git
cd mailsense/docker
cp .env.example .env
nano .env                      # обязательно: POSTGRES_PASSWORD, TZ, вход администратора
docker compose up -d --build
docker compose ps              # оба сервиса должны быть healthy
curl -s http://127.0.0.1:8123/api/health
```

Дальше откройте `http://<сервер>:8123` и войдите администратором.

**Минимум, который нужно заполнить в `.env`:**

| Переменная | Зачем |
|---|---|
| `POSTGRES_PASSWORD` | пароль базы документооборота (без него compose не поднимется) |
| `TZ` | часовой пояс предприятия: от него зависит, какой сегодня день, сроки и «просрочено» |
| `MAILSENSE_ADMIN_LOGINS` | доменные логины, которым выдаётся роль администратора; без списка администратора не будет ни у кого |
| `MAILSENSE_ADMIN_LOGIN` / `_PASSWORD` | аварийный локальный администратор: вход, когда каталог AD ещё не настроен или контроллер недоступен |

**Первый запуск.** На свежей базе документооборот включается сам (иначе вход не работал бы, а API
оставался открытым) — в журнале появится строка «Свежее серверное развёртывание: документооборот
включён автоматически». Миграции применяются при старте.

**Первичная настройка** (подробно — `docs/deploy-guide.md`):

1. Каталог AD: адрес контроллера домена, база поиска, служебная учётная запись для чтения
   (она нужна для поиска сотрудников, а не для входа работников).
2. Служебные ящики: внутренний (делопроизводство) и внешняя приёмная.
3. Почта для СЭД: выдать работникам ящики (Настройки → Пользователи и роли → «Почта для СЭД»),
   работник выбирает свой в Настройки → Личные настройки. Не выдали — работник сможет отправлять
   только со служебного ящика.
4. ИИ: адрес и модели выжимки и OCR, кнопка проверки связи.
5. Роли и типовые сроки — по регламенту организации.

Каталог, ящики и роли можно задать и заранее в `.env` (`MAILSENSE_LDAP_*`, `MAILSENSE_MAILBOXES`,
`MAILSENSE_SERVICE_MAILBOX`, `MAILSENSE_EXTERNAL_MAILBOX`) — тогда развёртывание идёт без захода
в интерфейс. **Значение из окружения применяется только там, где настройки ещё нет в базе:**
заданное администратором в интерфейсе всегда важнее.

## Клиент на рабочем месте

```bash
make package-win SERVER_URL=http://mail.enterprise.local:8123   # Windows-комплект (zip)
```

Адрес сервера можно вшить в комплект (`server.json` рядом с исполняемым файлом) или положить туда
позже руками. Если адрес не задан, приложение работает автономно и спросит адрес при настройке.

**Linux (.deb) собирается только в контейнере** — electron-builder для `.deb` требует `fpm` (Ruby),
которого на Windows нет:

```bash
docker build --network=host -f docker/Dockerfile.deb --output type=local,dest=deb-out .
# deb-out/mailsense-electron_0.1.4_amd64.deb
```

## Разработка

```bash
make install
make build        # core + docflow + server + web + electron
make run          # сервер: http://127.0.0.1:8123
make test         # юнит-тесты
```

⚠️ В ограниченной песочнице `make build` падает на esbuild (`spawn EPERM`) — пакеты собираются
через `tsc`, подробности в `docs/build.md`. Тесты веба быстрые (параллельные, ~3 минуты);
в песочнице, где запрещены дочерние процессы, используйте `pnpm --filter @mailsense/web test:serial`.
**Два прогона тестов одновременно на одной машине дают ложные падения** — см. `docs/rules.md`.

## Структура (pnpm workspace)

| Пакет | Назначение |
|---|---|
| `packages/core` | почта: БД SQLite, коннекторы IMAP/POP3, вложения, ИИ, каталог LDAP, сервисы |
| `packages/docflow` | документооборот (PostgreSQL): пользователи, роли, сессии, аудит, журнал, резолюции, «почта для СЭД» |
| `packages/server` | Express REST API + раздача SPA + standalone-запуск |
| `packages/web` | React 18 + Ant Design + Zustand (Vite) |
| `apps/electron` | Electron-оболочка и electron-builder (Windows zip, Linux .deb) |
| `docker/` | Dockerfile, Dockerfile.deb, docker-compose, пример `.env` |

Зависимость строго односторонняя: `docflow → core`.

## Конфигурация

Основные переменные (полный список — `docs/deploy.md`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MAILSENSE_DATA_DIR` | `./data` | каталог данных: SQLite, вложения, ключ шифрования, логи |
| `MAILSENSE_PORT` | `8123` | порт сервера |
| `DOCFLOW_DATABASE_URL` | — | PostgreSQL документооборота; без неё СЭД выключена |
| `MAILSENSE_DOCFLOW_ENABLED` | — | не задана: на свежей базе СЭД включается сама; `false` — сервер только с почтой |
| `MAILSENSE_AI_BASE_URL` / `_MODEL` | — | модель выжимки |
| `MAILSENSE_AI_OCR_BASE_URL` / `_OCR_MODEL` | — | модель OCR; может быть другим сервером |
| `MAILSENSE_LDAP_URL` / `_BASE_DN` / `_LOGIN` / `_PASSWORD` | — | каталог AD; логин — служебная учётка для чтения, не учётки работников |
| `MAILSENSE_MAILBOXES` | — | ящики JSON-массивом (развёртывание без интерфейса) |
| `MAILSENSE_SERVICE_MAILBOX` / `_EXTERNAL_MAILBOX` | — | роли служебных ящиков по адресу |
| `TZ` | `Europe/Moscow` в compose | часовой пояс предприятия |

## Известные ограничения

- **Офлайн-почты в режиме клиента нет**: письма и вложения живут на сервере, при его недоступности
  почтовые разделы отвечают 503 (черновики и шаблоны продолжают работать).
- **Система не решает за человека, что за письмо пришло**: ИИ только предлагает поля, регистрация
  и закрытие поручений — руками аппарата.
- **Свой ящик работника разрешён ему всегда** (совпадение с почтой или логином из каталога) — отзыв
  выдачи его не убирает. Это осознанное решение, а не дефект.
- Пакет `.deb` проверен структурно (`dpkg-deb`), но **не устанавливался на Linux-машину**.
- NSIS-установщик для Windows не собирается без wine — распространяется zip.
