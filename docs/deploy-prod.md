# Настройка на боевой контур (АСУП: MDaemon + AD asup.local)

Здесь — **что и где выставить в MailSense** для боевой инфраструктуры. Факты о самом контуре
(адреса, порты, формы логина, состояние сертификата) собраны в `test mail/PROD.md` — он лежит вне
репозитория, потому что содержит адреса и порядок работы. Общие правила развёртывания —
`docs/deploy-guide.md`; этот файл только про то, чем боевой контур отличается от стенда.

⚠️ **На живом контуре MailSense ещё не запускался.** Он проверен на стенде (docker-mailserver +
Samba AD), который повторяет структуру боевого: те же OU, кириллический логин при латинской почте,
те же роли. Но MDaemon и Windows AD — другие реализации, поэтому первый запуск делайте по шагам
раздела 5, а не «сразу в бой».

---

## 1. Что где задаётся

| Что | Где | Почему так |
|---|---|---|
| Пароль базы, вход администратора, часовой пояс, ИИ | `.env` сервера | нужно до первого запуска |
| Каталог AD: адрес, Base DN, формат логина, служебная учётка | `.env` (`MAILSENSE_LDAP_*`) **или** интерфейс: Настройки → Каталог | одинаково для всех рабочих мест — задаёт предприятие |
| Почтовые ящики (MDaemon): адрес, порт, шифрование, пароли | `.env` (`MAILSENSE_MAILBOXES`) **или** интерфейс: Настройки → Почта | пароли шифруются ключом из `data/` |
| Служебные ящики: внутренний (делопроизводство) и внешняя приёмная | `.env` или интерфейс: Настройки → Служебные ящики | это роли ящиков, а не адреса серверов |
| Комментарии, шифрование, «Строгий TLS» у ящика | интерфейс: Настройки → Почта | на боевом сертификат просрочен — строгий режим включать нельзя |
| Почта для СЭД: из чего работник выбирает | интерфейс: Пользователи и роли → «Почта для СЭД» | решение Р24 |
| Адрес сервера у клиентов | `SERVER_URL` при сборке комплекта или `server.json` | см. `docs/deploy.md` |

Правило одно: **значение из окружения применяется только там, где настройки ещё нет в базе.**
При каждом старте значение из файла перекрывает сохранённое в интерфейсе (пустая переменная
ничего не меняет) — развёртывание описано файлом .env.

## 2. Сервер: `.env`

```ini
TZ=Europe/Moscow
POSTGRES_PASSWORD=<пароль базы, не из документации>

# Кому выдаётся роль администратора при первом входе.
# ⚠️ Здесь именно sAMAccountName — на боевом контуре он КИРИЛЛИЦЕЙ (например «Лысенко_ОД»).
# Регистр не важен, форму @asup.local и ASUP\ пиcать НЕ надо.
MAILSENSE_ADMIN_LOGINS=Лысенко_ОД,<второй администратор>
MAILSENSE_ADMIN_LOGIN=admin            # аварийный локальный вход, если AD недоступен
MAILSENSE_ADMIN_PASSWORD=<пароль>

# Каталог (AD asup.local).
MAILSENSE_LDAP_ENABLED=true
MAILSENSE_LDAP_URL=ldap://192.168.1.40:389      # LDAPS 636 на боевом не отвечал
MAILSENSE_LDAP_BASE_DN=OU=KNIITMU,DC=asup,DC=local   # НЕ корень домена: см. раздел 5
MAILSENSE_LDAP_LOGIN_FORMAT=upn
MAILSENSE_LDAP_UPN_SUFFIX=@asup.local           # работник вводит «Лысенко_ОД»
MAILSENSE_LDAP_LOGIN=<служебная доменная учётка>
MAILSENSE_LDAP_PASSWORD=<её доменный пароль>
MAILSENSE_LDAP_REJECT_UNAUTHORIZED=false        # сертификат self-signed И просрочен

# Умолчания почтового сервера: работник вводит только адрес ящика и пароль.
# Задаются один раз на предприятие (или в интерфейсе: Настройки → Почта).
MAILSENSE_MAIL_DEFAULTS={"pop3":{"host":"192.168.1.10","port":995,"tls":"ssl","authType":"login"},"imap":{"host":"192.168.1.10","port":993,"tls":"ssl","authType":"login"},"smtp":{"host":"192.168.1.10","port":465,"tls":"ssl","authType":"login"}}

# Ящики MDaemon. Логин — ПОЛНЫЙ АДРЕС латиницей, пароль — ПОЧТОВЫЙ (не доменный).
MAILSENSE_MAILBOXES=[{"username":"lisenko_od@kniitmu.ru","password":"…","protocol":"pop3","host":"192.168.1.10","port":995,"tls":"ssl","authType":"login","smtpHost":"192.168.1.10","smtpPort":465,"smtpTls":"ssl","smtpUsername":"lisenko_od@kniitmu.ru","smtpPassword":"…"}]

MAILSENSE_SERVICE_MAILBOX=<адрес внутреннего ящика делопроизводства>
MAILSENSE_EXTERNAL_MAILBOX=<адрес внешней приёмной>

MAILSENSE_AI_BASE_URL=http://<внутренний ИИ>:<порт>/v1
MAILSENSE_AI_MODEL=<имя модели выжимки>
MAILSENSE_AI_OCR_BASE_URL=http://<внутренний ИИ>:<порт>/v1
MAILSENSE_AI_OCR_MODEL=<имя модели OCR>
```

Три значения, которые на боевом контуре отличаются от стенда и которые легко перепутать:

1. **`MAILSENSE_LDAP_BASE_DN` — `OU=KNIITMU,DC=asup,DC=local`, а не `DC=asup,DC=local`.**
   От корня AD отдаёт referrals на `CN=Configuration` и DNS-зоны, и клиент LDAP падает с
   «Operations error». В `ldapsearch` это незаметно: он referrals печатает комментариями.
2. **`MAILSENSE_LDAP_UPN_SUFFIX=@asup.local` обязателен.** В каталоге логин кириллицей
   (`Лысенко_ОД`), а работник вводит именно его. Без суффикса bind уходит без домена и AD отказывает.
3. **`MAILSENSE_ADMIN_LOGINS` — кириллицей.** Список сравнивается с `sAMAccountName` из каталога,
   а он на боевом контуре кириллический. Латинский вариант (`lisenko_od`) роль не выдаст.

## 3. Почтовые ящики MDaemon: точные значения

| Поле в интерфейсе | Значение | Почему |
|---|---|---|
| Протокол | **POP3** | так работает у пользователей (Thunderbird); IMAP тоже поддержан — 993 SSL |
| Сервер | `192.168.1.10` | MDaemon, FQDN mail.kniitmu.ru |
| Порт | `995` | альтернатива: `110` + шифрование STARTTLS |
| Шифрование | **SSL/TLS** | сертификат self-signed и **просрочен 03.03.2026** |
| Строгий TLS | **выключен** | иначе проверка сертификата оборвёт соединение |
| Аутентификация | **LOGIN** | MDaemon принимает LOGIN и PLAIN; доменные формы логина — нет |
| Логин | `lisenko_od@kniitmu.ru` | полный адрес **латиницей**; `ASUP\…` и `…@asup.local` дают access denied |
| Пароль | почтовый пароль работника | **не совпадает** с доменным |
| SMTP-сервер | `192.168.1.10` | |
| Порт SMTP | `465` | альтернатива: `587` + STARTTLS; `25` — без шифрования, AUTH разрешён |
| Шифрование SMTP | **SSL/TLS** | |
| Логин/пароль SMTP | те же, что у входящей | можно не заполнять — берутся из входящей |

После сохранения нажмите **«Проверить»** (входящая) и проверку SMTP: приложение само скажет,
что не так, вместо молчаливого отказа при первом сканировании.

⚠️ **Пароли почты и каталога — разные.** Почтовые пароли работников нужны администратору, который
заводит ящики; хранить их в MailSense не требуется — они шифруются ключом из `data/` и больше нигде
не выводятся (в журнал не попадают).

## 4. Клиенты

```bash
make package-win SERVER_URL=http://<сервер-mailsense>:8123
make package-deb SERVER_URL=http://<сервер-mailsense>:8123
```

Адрес ложится в пакет (`server.json` рядом с исполняемым файлом), работник его не меняет.
Браузерный вход с любого рабочего места: `http://<сервер-mailsense>:8123`.

Сеть: порт **8123** доступен только из внутренней сети; наружу сервер не выставляется. Удалённый
доступ — через существующий шлюз `gw-01.asup.local` («Континент TLS»), учётные данные доменные.
Порт базы данных наружу не публикуется вообще.

## 5. Порядок первого запуска на боевом (ничего не пропуская)

1. Развернуть сервер из `.env` (раздел 2), дождаться `healthy`, открыть `/api/health`.
2. Войти администратором (логин из `MAILSENSE_ADMIN_LOGINS`, доменный пароль).
3. **Каталог:** проверить адрес, Base DN `OU=KNIITMU,DC=asup,DC=local`, формат UPN и суффикс
   `@asup.local`; нажать проверку подключения. Затем найти в адресной книге живого сотрудника —
   **по фамилии кириллицей** (адрес ищется по `mail`, имя — по `cn`/`displayName`; по логину поиск
   бесполезен).
4. **Один тестовый ящик:** завести почту одного работника (POP3 995 SSL), нажать «Проверить»,
   затем запустить сканирование и убедиться, что письма появились.
5. **Служебные ящики:** назначить внутренний (делопроизводство) и внешнюю приёмную.
6. **Почта для СЭД:** назначить адреса ящиков аппарату и исполнителям (Пользователи и роли → «Почта для СЭД»),
   каждый выбирает свой ящик в личных настройках.
7. **ИИ:** указать адреса моделей выжимки и OCR, проверить связь кнопкой.
8. **Роли:** администратор и секретариат (аппарат) — с правами почты; руководитель, подписант,
   исполнитель почту не видят.
9. **Проверить цикл:** внешнее письмо → регистрация в журнале → поручение → утверждение подписантом
   → отправка исполнителям → отчёт → закрытие. Отправку проверить **на тестовый адрес**.
10. **Резервная копия:** `docker/data`, `docker/pgdata`, `docker/.env` — и проверить восстановление
    на тестовом сервере, а не «на слово».

## 6. Чего мы ещё не проверяли (честно)

- **POP3 против MDaemon.** Собственный POP3-клиент MailSense проверен на docker-mailserver. MDaemon
  может отдавать нестандартные ответы — если скан не пойдёт, смотрите `data/logs/mailsense.log`
  и присылайте строки обмена: клиент логирует команды и ответы.
- **Windows AD.** На стенде Samba AD; поведение referrals и кириллического UPN на Windows AD
  ожидается таким же, но подтверждения нет.
- **Просроченный сертификат.** Пока он такой, строгий TLS включать нельзя. После замены сертификата
  (`CN=mail.kniitmu.ru`) можно включить «Строгий TLS» и `MAILSENSE_LDAP_REJECT_UNAUTHORIZED=true`.
- **Размер каталога.** В AD около 718 учёток с `@kniitmu.ru`; поиск по `OU=KNIITMU` на стенде
  проверен на десятках записей, не на сотнях.
- **Нагрузка почты.** В боевом ящике могут быть тысячи писем; сканирование идёт по диапазону дат,
  первое лучше делать за месяц, а не за годы.
