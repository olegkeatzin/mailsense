# Настройки, режимы работы и развёртывание

## Конфигурация (env)

См. `packages/core/src/config.ts`. Ключевые:

| Переменная | Смысл |
|---|---|
| `MAILSENSE_DATA_DIR` | каталог данных (SQLite, вложения, логи) |
| `MAILSENSE_PORT` | порт сервера, по умолчанию 8123 |
| `MAILSENSE_AI_BASE_URL`, `MAILSENSE_AI_MODEL` | модель выжимки |
| `MAILSENSE_AI_OCR_BASE_URL`, `MAILSENSE_AI_OCR_MODEL` | модель OCR — **свой адрес и модель**, не обязательно те же, что у выжимки |
| `MAILSENSE_AI_API_KEY`, `_MULTIMODAL`, `_TIMEOUT_MS` | ключ, мультимодальность, таймаут ИИ |
| `MAILSENSE_AI_OCR_MAX_PAGES`, `MAILSENSE_AI_TEXT_MAX_PAGES` | лимиты страниц PDF (рендер для OCR и текстовый слой) |
| `MAILSENSE_MAILBOXES` | почтовые ящики JSON-массивом — развёртывание без захода в интерфейс |
| `MAILSENSE_LDAP_URL` / `_BASE_DN` | адрес и база поиска каталога (AD) |
| `MAILSENSE_LDAP_LOGIN` / `_PASSWORD` | **служебная** учётная запись для чтения каталога (поиск сотрудников, адресная книга), не учётки работников |
| `MAILSENSE_SERVICE_MAILBOX`, `MAILSENSE_EXTERNAL_MAILBOX` | роли служебных ящиков (внутренний, внешняя приёмная) по адресу |
| `MAILSENSE_MAIL_HOST` / `_PORT` / `_USER` / `_PASS` | засев ОДНОГО тестового ящика (стенд) |
| `MAILSENSE_SEED_ACCOUNT` | засевать ли дефолтный аккаунт |
| `DOCFLOW_DATABASE_URL` | PostgreSQL документооборота; без неё СЭД выключена |
| `MAILSENSE_DOCFLOW_URL` | режим клиента: адрес удалённого сервера |
| `MAILSENSE_ADMIN_LOGINS` | кому выдать роль администратора (через запятую) |
| `MAILSENSE_ADMIN_LOGIN` / `MAILSENSE_ADMIN_PASSWORD` | **аварийный локальный администратор** — вход, когда каталог ещё не настроен или контроллер домена недоступен |
| `MAILSENSE_DOCFLOW_ENABLED` | управление документооборотом при развёртывании: не задана — на свежей базе включается сам; `=true` включает явно и записывает настройку; `=false` только подавляет автовключение (сервер без СЭД) |
| `DOCFLOW_TEST_DATABASE_URL` | база для тестов СЭД |
| `TZ` | часовой пояс предприятия — им определяется «сегодня» для сроков, журнала и напоминаний |

⚠️ **Настройки из окружения применяются только к тому, чего ещё нет в базе.** Значения
`MAILSENSE_LDAP_*`, `MAILSENSE_MAILBOXES`, `MAILSENSE_SERVICE_MAILBOX`/`MAILSENSE_EXTERNAL_MAILBOX`
и `MAILSENSE_AI_*` заполняют настройки при первом запуске; заданное администратором в интерфейсе
всегда важнее и перезапуском контейнера не отменяется. Пароли (каталога и ящиков) хранятся
зашифрованными ключом из `data/`; ошибки засева не мешают старту — ищите в журнале строку
«Засев из окружения». Подробности и пример `.env` — в `docs/deploy-guide.md`.

⚠️ **Часовой пояс задаёт день предприятия.** Если `TZ` не задан, берётся пояс хоста, а на сервере это
часто UTC: тогда с 00:00 до 03:00 МСК вчерашний срок выглядит сегодняшним, а «Просрочено» приходит
на три часа позже — ровно в те часы, когда аппарат разбирает почту следующего дня. В `docker-compose.yml`
стоит `TZ=${TZ:-Europe/Moscow}`; при развёртывании без контейнера задайте `TZ` в окружении сервиса.

Дефолтный аккаунт засевается **только** если `MAILSENSE_SEED_ACCOUNT=true` И заданы
`MAILSENSE_MAIL_USER`+`MAILSENSE_MAIL_PASS`. По умолчанию (`false`) ничего не засевается —
в сборке жёстко зашитых учётных данных нет.

## Настройки

Серверная часть хранит свои в PostgreSQL (таблица `settings`): `docflow.enabled`,
`auth.sessionTtlHours`, `auth.localLoginEnabled` и настройки каталога `ldap.*`. Когда сервер работает,
именно он владелец `ldap.*`; core читает их через `LdapSettingsStore` (синхронно, из кэша в памяти),
а пишет асинхронно в PostgreSQL. Без сервера `ldap.*` остаются в локальной SQLite.

`security.corsOrigins` — всегда core; пока документооборот включён и список пуст, CORS не отдаётся
вовсе (SPA и API на одном origin).

### Почта для СЭД (Р24): кто чем отправляет

`docflow.serviceAccountId` — **служебный внутренний ящик предприятия**. Порядок выбора при отправке
документов (см. `docs/docflow.md`): явно указанный в запросе (обязан быть в разрешённых, иначе 403
`account_not_allowed`) → **личный выбранный ящик работника** (`edms.workAccountId`) → служебный внутренний.

⚠️ **«Первый подходящий» ящик запрещён.** Раньше отправка откатывалась на любой готовый ящик — от этого
отказались: официальное письмо не должно уходить с чужого адреса. Если отправлять не с чего, действие
отказывает с понятным текстом, а не подставляет другой ящик:

- выбранный ящик без настроенного SMTP → `smtp_not_configured`;
- выбранный ящик удалён из почты → `account_missing`;
- ящик не разрешён работнику → 403 `account_not_allowed`.

Кто попадает в разрешённые: служебный ящик предприятия, ящики, **выданные администратором**
(Настройки → Пользователи и роли → «Почта для СЭД»), и собственный ящик работника, адрес которого
совпал с его почтой или логином из каталога. **Свой ящик разрешён всегда** — отзыв выдачи его не
убирает (решение заказчика 2026-10-09).

Пошаговое руководство для администратора (требования, быстрый старт, папки на хосте, бэкапы,
обновление, TLS, чеклист приёмки) — в `docs/deploy-guide.md`. Учётки и проверки на тестовом
контуре — в `docs/stand.md`.

## Два режима работы

**Автономный сервер** — всё в одном процессе: почта (служебные ящики) + документооборот.
Клиенты подключаются браузером. Именно это разворачивается docker-образом.

**Клиент с удалённым сервером** (`MAILSENSE_DOCFLOW_URL`, в Electron — «Адрес сервера») —
целевая топология 0.1.4 (решение Р15–Р17): у каждого сотрудника Electron-приложение, сервер СЭД
разворачивается docker-образом и **держит служебные ящики аппарата**. Локальный backend поднимается
всегда и **проксирует на сервер и служебные пути, и почтовые** — см. `packages/server/src/proxy.ts`:

- проксируется: `/api/auth`, `/api/docflow`, `/api/journal`, `/api/users`, `/api/roles`, `/api/audit`,
  `/api/directory`, `/api/contacts`, `/api/emails`, `/api/accounts`, `/api/threads`, `/api/analysis`,
  `/api/import`, `/api/compose-template`, `/api/settings`, `/api/ai`;
- остаётся в клиенте (личное работника): `/api/drafts`, `/api/templates`, `/api/mail-profile`
  (личный профиль почты: имя отправителя, подпись, шаблоны — Р18; реализован), `/api/health`
  и статика SPA. «Почта для СЭД» сюда НЕ входит: это серверная настройка, иначе сервер не смог бы
  проверить право на ящик и отфильтровать очереди СЭД.

⚠️ **Офлайн-почты в этом режиме больше нет.** Письма, ящики и вложения живут на сервере, поэтому при
недоступном сервере почтовые пути отвечают 503 с понятным текстом (а не пустым списком), а черновики
и шаблоны продолжают работать. Это следствие варианта А: сервер — единственный держатель служебной
почты, и его доступность равна доступности почты аппарата.

⚠️ **Список проксируемых путей ведётся перечислением.** Новый личный путь автоматически остаётся
локальным (это и нужно), а новый серверный надо явно добавить в `MAIL_PREFIXES`/`DOCFLOW_PREFIXES` —
иначе он молча останется в клиенте.

### Адрес сервера в комплекте (как «вшить» его в пакет)

Приложение ищет адрес в таком порядке: `--server=` → **`server.json` рядом с исполняемым файлом**
(конфиг предприятия) → `server.json` в каталоге пользователя (личная настройка) → `MAILSENSE_SERVER_URL`
(принимается и прежнее имя `MAILSENSE_DOCFLOW_URL`) → автономный режим. Если адрес задан файлом
предприятия, в настройках он показан как «Адрес задан администратором — изменить нельзя», а личная
настройка и переменная окружения его **не перебивают**.

Два способа раздать адрес работникам:

1. **Собрать комплект с адресом внутри** (ничего не нужно делать на местах):

   ```bash
   make package-win SERVER_URL=http://mail.enterprise.local:8123   # Windows zip
   make package-deb  SERVER_URL=http://mail.enterprise.local:8123   # Linux .deb
   ```

   Сборка кладёт `server.json` рядом с исполняемым файлом прямо в архив — внутри пакета он
   оказывается по пути `server.json` (в `.deb` — рядом с бинарником в каталоге установки).
   Без `SERVER_URL` файл не добавляется: пакет остаётся автономным.

   На Linux это работает так же, как на Windows: `make package-deb SERVER_URL=…` (он же
   `make package-linux`) вшивает адрес тем же шагом `make-server-json`.

   ⚠️ **Не работает только сборка `.deb` с Windows** — electron-builder требует `fpm` (Ruby),
   которого там нет. Тогда пакет собирается в контейнере, адрес задаётся сборочным аргументом:

   ```bash
   docker build --network=host --build-arg SERVER_URL=http://mail.enterprise.local:8123 \
     -f docker/Dockerfile.deb --output type=local,dest=deb-out .
   ```

   Без `--build-arg SERVER_URL` файла в пакете нет — приложение спросит адрес при первом запуске
   (подробности и проверка пакета — в `docs/build.md`).

2. **Положить файл вручную** в уже собранный комплект: рядом с `MailSense.exe` (или рядом с
   бинарником в каталоге установки) создать `server.json`:

   ```json
   { "serverUrl": "http://mail.enterprise.local:8123" }
   ```

   **Где этот файл ищется после установки `.deb`:**

   | Путь | Для кого | Права |
   |---|---|---|
   | `/opt/MailSense/server.json` | все пользователи машины (адрес задан администратором, менять нельзя) | нужен root |
   | `~/.config/MailSense/server.json` | только этот работник (личная настройка) | права не нужны |

   Разово, без файла: запуск с аргументом `mailsense-electron --server=http://…` или переменной
   окружения `MAILSENSE_SERVER_URL`. Приоритет: аргумент → файл рядом с программой → личный файл →
   переменная. Если файл рядом с программой есть, но испорчен, приложение **не** ищет адрес дальше —
   это защита от молчаливого подключения не к тому серверу.

   Пересборка не нужна — приложение читает файл при запуске.

⚠️ **Пустой или испорченный файл предприятия — это ошибка, а не «ничего не задано».** Правило
«присутствие важнее содержимого»: если файл есть, но адрес в нём негодный, приложение честно
сообщает об этом и **не** ищет адрес дальше — иначе опечатка администратора выглядела бы как
«работает», а работник молча уехал бы на другой сервер. Поэтому файл либо правильный, либо его нет.

Прокси монтируется **до** `express.json()`, иначе тело запроса (вложения) дойдёт до сервера пустым.

Почему прокси, а не прямые запросы из renderer: один origin — не нужен CORS, сессионная cookie живёт
на `127.0.0.1` и не требует `SameSite=None` + HTTPS. Адрес сервера задаётся через
«Настройки → Документооборот» (IPC `server-config:set` в Electron), после смены нужен перезапуск.

⚠️ **Настройки каталога (`ldap.*`) задаются на сервере.** В режиме клиента `/api/directory` и
`/api/contacts` проксируются, так что клиент не хранит настройки LDAP и не ходит в каталог сам:
и вход, и адресная книга идут через сервер. Вкладка «Каталог (LDAP)» у пользователя без права
`settings.manage` показывается только для чтения.

⚠️ В режиме клиента локальная база документооборота **не инициализируется** — иначе у пользователя
оказалось бы два разных журнала. Поэтому `createApp` не должен вызывать `isDocflowEnabled()` в этом
режиме (иначе падение на старте: «База документооборота не инициализирована»).

## Развёртывание

```bash
docker compose -f docker/docker-compose.yml up -d --build     # сервер + SPA на :8123
```

Поднимаются два сервиса: `postgres` (том `mailsense-pg`) и само приложение (том `mailsense-data`
с локальной SQLite). Адрес базы документооборота приложение получает через `DOCFLOW_DATABASE_URL`.
Клиент настраивается на сервер переменной `MAILSENSE_DOCFLOW_URL`.

⚠️ **Открытый порт без входа.** `startServer` предупреждает, если сервер слушает не-`127.0.0.1`,
а документооборот выключен: API в этот момент открыт любому в сети.
