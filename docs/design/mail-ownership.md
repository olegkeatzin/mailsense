# Ящики принадлежат человеку, роли и настройки — редактируемые

Решение заказчика (13.10.2026) и разбор найденных проблем. Документ — контракт для этапов,
чтобы правки не разъехались.

## Что было не так

| Проблема | Причина в коде |
|---|---|
| Почта «перебрасывается между аккаунтами», пропадает свой ящик и появляется чужой | `listAccounts()` отдаёт **всю** таблицу `accounts`; `/api/accounts` доступен по `mail.view`, а `/api/emails?accountId=…` не проверяет владельца. Это утечка: чужую почту можно читать, чужой ящик — удалить (`settings.manage`) |
| Работник без ролей не может ничего, даже завести свой ящик | свой ящик требует права управления настройками предприятия (`settings.manage`) |
| «Почта для СЭД» выбирается из чужих ящиков и не настраивается | дропдаун строится по общему списку ящиков; выбор — отдельная сущность от вкладки «Почта» |
| Пароли всех ящиков вводит администратор | ящик = запись с паролем, введённым тем, кто его создал |

## Решение (согласовано)

1. **Пароль ящика вводит только владелец.** Пароль хранится на сервере зашифрованным
   (тем же `secrets`), привязанным к работнику. Администратор паролей не вводит.
2. **Служебные ящики** (делопроизводство, внешняя приёмная) — тоже: пароль вводит тот,
   кто этим ящиком пользуется.
3. **Адрес для СЭД** администратор назначает работнику **без пароля**; по умолчанию адрес
   подтягивается из LDAP (атрибут `mail`). Работник вводит пароль у себя.
4. **Роли — с нуля.** Фиксированный набор и преднастроенные права убираются; администратор
   сам создаёт роли и расставляет галочки прав. Остаётся только вход администратора
   (иначе систему некому настроить).
5. **Умолчания почтового сервера** (хост/порт/TLS/тип аутентификации для POP3/IMAP и SMTP)
   задаются на сервере: в `.env` и на вкладке настроек. Работник вводит только логин и пароль.
6. **Настройки** — вертикальный список категорий слева, фиксированный размер окна.

## Модель данных

**Этап 1 (этот).** Владелец ящика — у записи `accounts`:
```
accounts.owner_user_id TEXT   -- учётная запись работника (LDAP-логин); NULL = ничей (старые записи)
```
Правила:
* видимость: работник видит **только свои** ящики (`listAccountsForUser`);
* чтение и изменение почты — только по своему ящику (проверка на каждом маршруте, а не только права);
* создание ящика доступно **любому вошедшему** (это личный ящик, не настройка предприятия);
* удаление/правка — только владелец;
* строки без владельца видны только тем, у кого `settings.manage` (архив прошлых установок):
  их можно удалить или переназначить.

**Этап 2.** Пароли отделяются от ящика: `account_credentials(account_id, user_id,
password_encrypted, smtp_password_encrypted)`. Ящик = адрес + параметры сервера (один на адрес,
без дублирования писем), пароль — у каждого свой. Тогда «каждый вводит свой пароль» работает
и для общего служебного ящика.

**Этап 3.** `edms_mail_assignment`: администратор назначает работнику **адрес** (из LDAP), без пароля.
Выбор «Почта для СЭД» = ящик, на который у работника есть пароль.
